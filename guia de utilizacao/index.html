>_ ./omnigraph.sh

Mapeie qualquer projeto num grafo de conhecimento que você consulta em vez de vasculhar arquivos.

O OmniGraph lê seu código, docs, PDFs e imagens e monta um grafo interativo — local, privado, sem embeddings. Este guia mostra o caminho prático do zero à primeira consulta.

100% local AST via tree-sitter grafo real, não vetor MCP para IA

00O que é

Grafo em vez de grep

Cada arquivo, classe, função e conexão vira um nó ou aresta. Você pergunta "qual o caminho entre A e B?" ou "o que é este módulo?" e recebe a resposta traçada no grafo — em vez de ler dezenas de arquivos na mão.

🗺️

Código de graça

Parsing por AST com tree-sitter: determinístico, sem LLM, nada sai da máquina.

🔗

Toda aresta é explicada

Cada conexão é EXTRACTED (explícita) ou INFERRED (deduzida).

🔒

Privado

Sem vetor, sem nuvem. Um grafo que você percorre em graph.html.

01Instalação

A partir de um clone, com uv

O pacote não está num índice público — instale direto do repositório clonado. O uv cria o ambiente isolado e registra os binários omnigraph e omnigraph-mcp.

terminal
# clone o repositório e entre nele
$ git clone https://github.com/Zespek/OmniGraph.git && cd OmniGraph

# instala o CLI a partir do clone local
$ uv tool install --from . omnigraph

# registra a skill no seu assistente de IA (Claude, Cursor, etc.)
$ omnigraph install
Não achou o comando depois? Rode uv tool update-shell e reabra o terminal.

02Extrair o grafo

Do projeto ao graph.json

Na raiz do projeto que você quer mapear. O resultado fica em omnigraph-out/ — o grafo (graph.json), o relatório e um graph.html navegável.

terminal
$ omnigraph extract .        # AST + passe semântico; gera omnigraph-out/graph.json
$ omnigraph update .         # reextrai só o código e atualiza (sem LLM, sem custo)
$ omnigraph cluster-only .  # reagrupa comunidades e regenera o relatório
Dica: rode omnigraph update . depois de mexer no código para manter o grafo em dia — é rápido e não chama API nenhuma.

03Consultar

Perguntas ao grafo, não aos arquivos
terminal
# menor caminho entre dois nós
$ omnigraph path "LoginView" "Database"

# explicação em linguagem simples de um nó e seus vizinhos
$ omnigraph explain "PaymentService"

# diagnostica risco de arestas colapsadas no grafo
$ omnigraph diagnose multigraph
ComandoPara quê
path "A" "B"Traça o caminho mais curto entre dois nós
explain "X"Descreve um nó e o que o cerca, em português claro
clone <url>Clona um repo do GitHub e prepara para o /omnigraph
diagnose multigraphAponta onde arestas de mesmo par podem se colapsar

04Servir via MCP

Exponha o grafo para o assistente de IA

O omnigraph-mcp serve as ferramentas de consulta por protocolo MCP. Dois transportes: stdio (padrão, um dev — o assistente sobe sozinho) e HTTP (serviço compartilhado).

stdio — local
$ omnigraph-mcp                       # lê omnigraph-out/graph.json
$ omnigraph-mcp caminho/graph.json     # ou um grafo específico
http — serviço compartilhado
$ export OMNIGRAPH_API_KEY="uma-chave-secreta"
$ omnigraph-mcp graph.json --transport http --host 0.0.0.0 --port 8080
FlagPadrãoPara quê
--host127.0.0.1Interface. 0.0.0.0 expõe na rede — só com chave
--port8080Porta HTTP
--path/mcpCaminho: http://host:porta/mcp
--api-key—Exige a chave (ou OMNIGRAPH_API_KEY)
Expôs na rede? Use chave. Com --host 0.0.0.0 sem --api-key, qualquer um na rede consulta seu grafo.

05Docker

O servidor HTTP em container

O Dockerfile da raiz empacota o servidor HTTP. Monte o diretório do grafo em /data.

docker
$ docker build -t omnigraph-mcp .
$ docker run --rm -p 8080:8080 -v "$PWD/omnigraph-out:/data" \
    omnigraph-mcp /data/graph.json --transport http --host 0.0.0.0 --port 8080

O container roda como usuário sem privilégio e escuta em :8080.
